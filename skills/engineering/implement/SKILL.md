# Implement

Accept exactly one explicitly Mission-authorized Ticket identity. In this same root invocation, load and follow installed `dispatch-tickets` with the identity unchanged in this complete one-item Mission plan:

```json
{"phases":[["<owner>/<repository>#<ticket>"]],"blockers":[],"conflicts":[]}
```

State that Mission authorization is explicit for this complete plan and that the empty relation arrays are complete because all external blockers and conflicts were resolved before authorization. The dispatcher then validates and freezes the plan and creates the fresh `orchestrate` Ticket coordinator.

If the invocation does not explicitly select exactly one fully qualified Ticket, report that Mission authorization is missing or invalid and stop before loading the dispatcher. Do not read Ticket or repository content, call `orchestrate`, create a child, or perform implementation, coordination, review, verification, or delivery here. This skill is only a one-Ticket convenience entry and owns no execution path independent of `dispatch-tickets`.
